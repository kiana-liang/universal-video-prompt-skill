# 观测隔离区 · 填好的模型档案

> # ⛔ 写提示词的时候不要打开这个文件。
>
> 这里是**已经跑过的观测记录**，不是写作依据。它和[案例库](case-library.zh-CN.md)是同一个结构的两面：
> 案例库隔离的是"可抄的皮"（会让你**多抄**），本文件隔离的是"我对模型能力的理解"（会让你**少写**）。
>
> **少写比多抄更难发现**：抄错了看得出来，而"因为觉得模型做不好所以没写"这件事，
> 在输出里没有任何痕迹——你只会看到效果没达到预期，却找不到原因。
>
> ## 两个用途，只有第二个允许在写作前发生
>
> | 用途 | 什么时候 | 读哪部分 |
> |---|---|---|
> | **事后诊断** | 跑完了、效果不对、想知道发生了什么 | 全文 |
> | **编译期降级** | 提交之前 | **只读「能力位层」里那些违反就会报错的硬约束**（时长 enum、分辨率枚举、比例、参考图数量、寻址语法） |
>
> **偏置层与已知失败模式在写作期一律不读。** 它们不构成"不要写 X"——
> 照[宪法](constitution.zh-CN.md)第九条，一个槽的作用会溢出它自己的作用域，
> 任何单槽观测都不足以决定该不该写。已经因此犯过一次错：某个模型的音乐段被记成「无效、可删」，
> 后来的受控对照显示它真正改变的是画面节奏。
>
> ## 顺序是死的
>
> **先按这条片子要什么把决策清单写全 → 再让硬能力位触发降级 → 降级必须报告。**
> 反过来（先看档案、再决定写什么）就是本文件要防的那件事。

## 填好的示例：`bytedance/seedance-2.0`

```markdown
# 模型档案：bytedance/seedance-2.0

最后核实：2026-08-03 · 服务：Atlas Cloud

## 能力位层

| 字段 | 值 | 如何核实 |
|---|---|---|
| 素材寻址语法 | `@image1`、`@image2`… | 生成实测 |
| 素材数量上限 | 9 张图 | 厂商文档 |
| 一次生成能否多镜头 | 能——带切点的有序段落 | 15 秒多段生成 |
| 时长范围 | 4–15s | 厂商文档 |
| 原生音频 | 有 | 开启音频的生成 |
| 时序遵循度 | 15 秒的片子里请求拍点**整体晚约 2 秒**；段落**顺序稳** | 对着带时间戳的提示词做的受控 15 秒实测 |
| 建议粒度 | **分段** | 由上一行推出 |
| prompt 长度耐受性 | **高。** 加长版本保住了手、开场变形、手绘质感，还吃下了新增拍点 | 同一份决策清单的 v3 |

## 偏置层

| 字段 | 值 | 如何核实 |
|---|---|---|
| 默认审美偏置 | 镜头先验很强；稀疏提示词理解得好，会合理即兴 | 与过度指定版本做 A/B |
| 有效的反默认写法 | **按工具命名，不要命名抽象属性。** `蜡笔／彩铅／粗笔刷，看得见排线方向、涂色不均、毛边` 给出了真正的手绘笔触 | 同一份手绘 VFX 决策清单的受控 A/B |
| 未按预期生效 / 过冲的写法 | **`保持平面图形、绝不写实` —— 被精确满足，但没带来预期的手绘感。** 模型用光滑的霓虹管矢量描边加均匀填充满足了它：平面，但完全不手绘。在同一份决策清单上只把这一条锁换成工具名，结果直接反转 | 同上 |
| 未按预期生效 / 过冲的写法 | **喂故事板网格过度指定，观测到比纯文字 staging 更差** —— 会压掉让重特效镜头成立的运镜先验 | 同一段落的 A/B |
| 负向锁行为 | 会被尊重。前置 | 迭代 |
| 参考图与文字的优先级 | **图赢。** 构图参考会覆盖写出来的构图 | 迭代 |

## 已知失败模式

| 症状 | 细节 | 处理 |
|---|---|---|
| 小字出错 | UI 标签与招牌出现字符级错误，小字乱码 | 缩短字符串、拉大字距字号，或用图形符号替代文字 |
| 列表项漏画 | 枚举的菜单项只画出一部分 | 减少条目数，或改用图形符号 |
| 运镜被忽略 | 写明的运镜被跳过，段落其余部分正常 | 把运镜改写成该段的主要意图，或接受并重新构图 |
| 时间轴漂移 | 整条时间轴后移，15 秒里约 2 秒 | 用分段；若必须秒级，把拍点写早并核实 |
| **超载时丢段** | 15 秒装**四段**时只渲染了第 1 段和第 4 段——中间两段**整个跳过**，不是延迟。改成五段更短、每段事件更密之后**没有**复现 | 把 15 秒里约 4 个不同状态变化当作上限。需要更多就缩短每段、提高密度，或拆成多次请求 |

## 编译注记

- 输出 `@imageN`。绝不用方括号或拼写形式的素材标签
- 默认 `分段`
- 重特效与大场面段落优先文字驱动 staging，不要喂故事板网格
- 构图参考与写出来的构图冲突时，删掉写的那份——它反正会输，只是增加噪音
```

## 填好的示例：`minimax/h3/text-to-video`

实测日期 2026-08-06/07，走 Atlas Cloud REST 路线。**同路线内的观察，换路线要重测**（同一模型在厂商自有平台上的行为已知不同，见文末）。

## 能力位层

| 字段 | 值 | 如何核实 |
|---|---|---|
| 素材寻址语法 | 本条目为纯文生，不适用 | — |
| 一次生成能否多镜头 | **能**——15 秒内 17 个硬切无问题 | 多次生成实测 |
| 是否支持硬切 | **能**，且能做 0.1–0.15s 级的逐拍闪频（实测约 10 次/秒） | 抽密集帧计数 |
| 时长范围 | **4–15s，上限 15 硬性** | 提交 30 被上游拒（见「已知失败模式」） |
| 分辨率选项 | `768P`(1344×768) / `2K`(2560×1440)，24fps | schema + 产物实测 |
| 原生音频 | **原生，默认产出，没有开关参数，关不掉** | schema 无 `generate_audio`，产物仍带 AAC 音轨 |
| 时序遵循度 | 本路线**测不出**。见「编译注记」——不要把音画同步精度当成时序遵循度 | — |
| 建议粒度 | **分段**。同决策清单只改拍点标注、每臂 n=2 的对照里，秒级与分段**无可测差异**；按「取最松粒度」选分段 | 受控对照 |
| prompt 长度耐受性 | **高。** 2300–2400 字符、九个段落标记、十条负向，结构全部被执行 | 多次生成 |

## 偏置层

| 字段 | 值 | 如何核实 |
|---|---|---|
| 默认审美偏置 | **片型词是强指令。** 「动漫／赛璐璐」会把画面拽向立体光影、渐变、高光与**肤色**，压过「扁平矢量」「无渐变」「无描边」三条负向 | 同决策清单只改片型词的三点对照 |
| 有效的反默认写法 | **成组的定向禁令**（禁3D效果／禁立体建模／禁真实空间纵深／禁三维透视渲染／禁CG质感）。保留术语+配平 优于 删掉术语 | 删词版画风回来但丢造型质量；配平版两者都有 |
| 未按预期生效 / 过冲的写法 | 写「不要牌点字符」，两版均**未观测到**该内容消失；改成正向描述（「牌面正中一个巨大花色符号占七成，牌角空白」）后立刻改善 | 逐版对照 |
| 负向锁行为 | 整类质感的负向**观测到生效**（写实光影／3D／CG质感／肤色／渐变）；具体图形内容的负向**未观测到生效**，改成正向描述后生效 | 同上 |
| 语言敏感性 | 中文提示词实测有效。**英文未测** —— 具名风格术语的英文原形是否带同强度偏置，未知 | — |
| 画面内文字 | 短英文大写 + 拉字距：多次生成**均干净**（`WHITE RABBIT`）；短字符（牌点、编号）：多次生成**均出现字符错误**，糊成别的字母 | 多次生成 |
| 分辨率与画风稳定性 | **无关联，是抽卡。** 2K 三次里崩过一次（长写实脸 + 标签假文字），768P 三次干净——样本太小，别当规律 | n=3 / n=3 |
| 运行间方差 | **大。** 同一提示词四次运行音量跨度 16 dB；近静止帧占比在同臂内可差 10.5pp；切点数可差一倍 | 逐字相同提示词的重复运行 |

## 已知失败模式

- **音轨不遵循指定的 BPM 数值。** 指定 `132BPM` + 「N 秒后鼓点进入」+「结尾抽空」，音轨侧均未按数值发生（132BPM 整拍贴合度 1%，约等于随机）。
  ⚠️ **这条只覆盖"音轨是否遵循数值"，不构成"这一槽没用"。** 后来的受控对照（同一决策清单只追加一个节拍骨架段，其余逐字不动）显示它改变的是**别处**：
  画面 YUV 突变 22→27 处、突变间隔标准差 0.738→0.548、基线帧间差中位数 0.410→0.478、音轨点间隔 0.170s→0.265s。
  数值调高（120→132）则出现**事件局部爆发、整体更不均**（定格 22%→37%，54% 的事件挤进一个 3 秒区段）。
  **可用的结论**：写"有节拍骨架"有效，写"多少 BPM"不精确，且数值不是越高越好。n=1/臂，方向可信数值不可信。
- **`duration` 超出 enum 时，聚合路线不会在提交期报错。** 网关收下请求、返回成功、创建 prediction，再由上游拒（`status=failed`, `executionTime=0`）。**「任务创建成功」不等于参数被接受**——SKILL.md 那条「被拒不创建任务、不花钱」在这条路线上不成立。
- 给模型过多自由度的段落会脱离画风：一段写成「侧脸／手部／轮廓／旋转刻度不断重叠」的抽象蒙太奇，出现了偏绘画涂抹的质感。那类段落要额外加一句 pose-to-pose 约束。

## 编译注记

- **原生音频与自己的切点锚死在 0.8–1.0 帧（n=2 复现，8/8 与 7/7 命中）。** 这是模型内部行为，**与提示词无关** —— 提示词里没有任何时间戳、也没有要音频，同步照样出现。
  - 由此推出两条:①**不要把这个精度当成时序遵循度**记档案，那是两回事;②**用原生音频等于白拿一个帧级卡点**，换后期配乐会把它作废。
- 音量在 −9.6 ~ −25.6 dB 之间随机波动，成片要过一遍响度归一化。
- **计价按分辨率分档**，高分辨率档单价明显更高——分辨率是成本决策不只是画质决策。具体金额以服务商当时的价目为准，本文件不记。
- **厂商自有平台的行为不同**:观察到时长写在提示词散文里（「生成一支约20秒」→ 成片 26.77s，**超时约 34%**），且音乐规格在那条路线上生效。跨路线的结论不能互相搬。

| 字段 | 值 | 如何核实 |
|---|---|---|
| 未指定音频内容时的行为 | **写了「用原生音频」但不写具体内容，模型自行给出音乐与音效，且与剧情节奏对得上**（评价来自看片人，非测量） | v3 / v4 成片 |
| 参考图与文字的优先级 | 写明「不要用 @Image1 的构图取景与空间关系」之后，画面按文字给出真实纵深，未被参考图的平面构图带走 | v3 → v4 |

## 2026-08-10 · `minimax/h3` 接龙路线的新观测

**记录形式照[宪法](constitution.zh-CN.md)第九条：只记「我写了 X，观测到 Y」，不下"所以该不该写"的结论。**

### 能力位（硬约束，编译期可用）

| 观测 | 内容 |
|---|---|
| `image` 的 Base64 格式 | **裸 base64 字符串直接通过**，不需要 `data:image/jpeg;base64,` 前缀（两次提交、768P 与 2K 各一次） |
| 接龙可行性 | 首帧 → 15s i2v，**五个秒级区间的事件全部发生**，不是"只对首帧做微动" |
| 画幅继承 | `ratio` 只有 `adaptive`；2K 首帧（2560×1440）出 2K，768P 首帧出 1344×768 |

### 写了什么 → 观测到什么

| 我写的 | 观测到的 |
|---|---|
| 画面内文字 `JOE`（只写画面，**没写任何人声**） | **音轨里自发出现一个女声念出 "JOE"**。抽帧与帧间差分都测不到这一项，是人耳听出来的 |
| 一行刻痕数字（未指定内容） | 渲染出清晰的 8 位数字 `20397504`，字形干净 |
| 「在两帧内复制成五个横向排开，再高速合回一个」 | 五个同形物横向排开、合回，一次达成 |
| 「速度线自四边向重音点集中」「集中线自主体向外爆开」 | 出现，形态是放射状细线，密度很高 |
| 「单帧纯白冲击帧」 | 出现（抽帧里可见整格近白 + 放射线） |
| 「同一条轮廓线纵向拉伸变形，成为另一个形象的轮廓起点」 | **首帧那个主体被放大**，没有变成另一个形象。改写成「完全吞没、彻底消失、本段不再出现该类形象」并让新主体独立重建 |
| 三层反向视差（底色/雨线/前景各自速度与方向） | 帧间差中位数：段1 0.688 / 段2 0.744 / 段3 0.934 |

### 未指定的槽位由模型自己填，两次运行可能填成不同的东西

同一份提示词只写了「箱内浮出骨白色骨架线稿」，**没有指定物种**。两条分辨率链（唯一变量是 `resolution`）：

| 臂 | 观测到的骨架 |
|---|---|
| 768P | **四足动物骨架**（马的头骨与四肢） |
| 2K | **人类骨架**（头骨、肋骨、骨盆、四肢） |

**下游影响是连锁的**：768P 那条里马骨与后续的木马形状一致，
于是「骨架胸腔的矩形空缺变成木马侧影」这个图形匹配切执行得异常顺，
"马"成为该段的视觉主体，并被交接到下一段的首帧，导致下一段的巨像被执行成一匹巨马。

**可用的一条**：一个槽没写明，模型会替你填，而且**两次可能填得不一样**；
如果那个内容会被交接到下一段的首帧，偏差会沿着接龙链往下传。

### 状态查询返回 500 时，响应体里可能带着终态

一次 2K 的 i2v 任务：状态查询持续返回 **HTTP 500**，但 500 的响应体里是

```json
{"code":500, "message":"content blocked by moderation",
 "data":{"status":"failed", "executionTime":0, "latency_ms":125591}}
```

**「状态查询报错不是失败」这条规则不完整**：必须先解析响应体，
确认里面没有终态，才能当成网络抖动继续轮。否则会一直轮一个已经死掉的任务。

配套修正：**`executionTime=0` 不是判据，`status` 才是。**
同一天的另两次任务 `executionTime` 也是 0，但 `status=completed` 且正常出片。

### 同一份提示词，一个分辨率被审核拦、另一个通过

同一份提示词（逐字相同）、同一段内容，唯一差别是首帧与分辨率：

| 臂 | 结果 |
|---|---|
| 768P | 正常出片 |
| 2K | `failed` / `content blocked by moderation`，`latency_ms=125591` |

`latency_ms` 两分钟说明**审核发生在生成过程中或之后，不是提交期拦截**。

**后续**：同一份提示词、同一首帧、同一分辨率**原样重提一次 → `completed`**。

| 次 | prediction | 结果 |
|---|---|---|
| 1 | `5d9d4f02…` | `failed` / content blocked by moderation |
| 2 | `5bf695f1…` | `completed` |

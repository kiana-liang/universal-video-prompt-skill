# 填槽与反推

[spec-format.zh-CN.md](spec-format.zh-CN.md) 定义了槽是什么。这份文件讲**槽是空的，怎么填满**。

槽表本身与输入形态无关。用户交过来的东西有三种，目标是同一个：

| 输入 | 路线 | 主要风险 |
|---|---|---|
| 一个题材 / 故事 | **补足** —— 从命题推出其余各槽 | 靠形容词堆填满，看着满其实空 |
| 一段美学描述 / 参考图 | **补足 + 部分反推** | 把「看到的」照抄成槽值，不做归因 |
| 一条成片 / 别人的提示词 | **反推** —— 从产物还原决策 | 把观测到的东西全部当成决策 |

**先判定路线，再动手。** 混着走是白费功夫：补足要自己憋命题，反推**不许**自己憋——命题已经在产物里了，憋一个新的等于扔掉输入。

### 输入是一张图时，先分清它是首帧还是参考图

两者的**选法不同**，因为决定它们位置的东西不同：

| | 位置由什么决定 | 因此 |
|---|---|---|
| **首帧** | **叙事** —— 它必须是故事的第 0 帧 | 没得选 |
| **参考图** | **信息量** —— 它只需要承载得多 | **可以是一张片中不出现的设定图** |

⚠️ **默认动作（拿第一帧当参考图）经常恰好选中最弱的一帧。**

实测：一条片子的开场是主体蜷卧睡觉 —— 身体蜷成一团、身份不变量看不清，几样关键元素还没进画面，
是全片信息量**最低**的一帧。改用一张专门造的设定图（主体正面居中、全部元素各在其位）之后，
同一份提示词一次锁住了七样：媒介质感、配色、主体的全部身份不变量、物件造型与分层、构图法则、空间关系、配色范围。

**判据：这一帧同时承载了几样锁？承载得最多的那一帧赢，不管它在片中的位置。**

代价要一起交代：换来信息量，**第 0 帧就不再被钉死** —— 开场姿态必须靠提示词写实，这一条不能省。

## 补足

用户只给了题材时，按依赖顺序填，不要按槽表顺序填：

1. **导演命题**先写。一句话。它是后面所有槽的裁决依据，也是唯一不能从别处推出来的槽
2. **片型**。已跑通的片型直接载入 DNA 换皮，不要重推（见 [film-type-dna.zh-CN.md](film-type-dna.zh-CN.md)）
3. **粒度**。属于 DNA；从零写时才问，且要带理由地建议，不要甩空选择题
4. 其余槽从命题推
5. **负向最后写**，且只写这条片子真的可能产出、重做又很贵的东西

**空着比凑字数好。** 一个填不出内容的槽，说明它对这条片子不重要，或者命题还没想清楚——两种情况都不该用形容词补上。

## 反推

从一条成片、一张参考图或别人的提示词，还原出填好的槽。

### 流程

1. **先查客观事实，再看画面。** 时长、分辨率、帧率、容器元数据、音轨是否存在
2. **切分结构。** 切点、每段的可见末态
3. **走音频通道**（见下）
4. **填桶① → 桶② → 桶③**，顺序固定，否则串味
5. **归因**，把结果分流（见下）
6. **写覆盖声明**（见下）

### 反推的四条规则

**① 容器元数据先查，成本近零。**
生产方标识、任务 ID、编码器、分发痕迹都在那儿。它能定「谁生成的」，也能识别出哪些参数是分发管线的转码值、**不能当模型规格**（非标准宽高比通常是转码裁的）。

**它不能定段数。** 段数要靠模型的时长上限反推，而上限只能问人或实测。**平台 API 的参数枚举既不能证明模型上限，也不能用来反推段数。**

**探测上限时注意聚合平台的行为差异。** SKILL.md 讲的「直接提交你真正想要的值，被拒不创建任务、不花钱」在直连厂商时成立；**在聚合平台上可能不成立** —— 网关提交时不校验，返回成功并创建任务，再由上游拒掉。要预期一个 created-then-failed 的任务，而不是一个提交期错误。**看到「任务创建成功」不等于参数被接受。**

**② 音频是信息密度最高的通道，而且能数值化。**
音量包络给出整片结构（前奏／主段／落点／尾奏），提取 onset 与切点逐一比对给出的是硬数字而不是印象。桶① 的片型、桶③ 的分段边界都能从这里读出来。

有音轨就走这条，不要只看画面。

**③ 观测精度 ≠ 该写进决策清单的精度。**
这是反推特有的坑，正向流程里不存在。在成片上量到帧级的音画同步，照抄成秒级时间戳会让下一次生成更差——因为那个精度可能不是提示词给的。

**反推必须多一步归因**：这条特征是提示词给的，还是模型自己给的？

| 归因 | 处理 |
|---|---|
| 提示词给的 | 写进决策清单 |
| 模型内部行为 | 记进[模型档案](model-profile-schema.zh-CN.md)，**不写进决策清单** |
| 分发管线造成的 | 丢掉 |

判据：想想写提示词的那一刻，这个信息存在吗？——但注意反向陷阱：**如果作者把它写进了同一条提示词（例如音乐结构），那它就存在。** 别因为它是生成物就假定它不可指定。

**④ 单一阈值数切点会系统性漏掉节奏段。**
背景反相、色块闪频这类节奏手法**不改变画面内容**，只改变图形几何，场景检测在常规阈值下检不出来。结果是把一段每秒反相八次的高密度段读成「一个静镜」。

多档阈值各跑一次，并且抽密集帧（≥6fps）亲眼看。

### 结果要分流

反推的产物**不全属于决策清单**。按三层可移植性分开存：

| 层 | 例子 | 去哪儿 |
|---|---|---|
| 语言层 | 三桶各槽、末态、可观察线索、手法词表 | 决策清单 |
| 偏置层 | 反默认后缀的观测、哪些负向锁未按预期生效、片型词的偏置强度 | 模型档案 |
| 能力位层 | 时长上限、能否一次多镜头、原生音频、时序遵循度 | 模型档案 |

**混着存是反推最贵的错误**：一条只在某个模型上成立的规则被写进决策清单，下次换模型时会带着上一个模型的怪癖去写提示词。

同理，**从反推里抽片型 DNA 时，模型相关的条件不算 DNA**（见 film-type-dna.zh-CN.md「添加新片型」第 5 条）。

### 覆盖声明是必须的

反推靠抽帧，而抽帧有盲区（见 SKILL.md §6）。交付反推结果时必须明说结论覆盖哪一半：

| 维度 | 抽帧能定吗 |
|---|---|
| 质感、构图、配色、身份、末态 | 能 |
| 切点节奏、音画同步 | 能，且应给数值 |
| 镜头内运动质量、插帧平滑度、形变 | **不能** |

要么看回放，要么写明未覆盖。**不要凭静帧下整体结论**——一条片子可能每一帧都赢、动态全输。

---

## 反推之后

反推产出的是一份填好的决策清单，它和手写的决策清单地位相同：照常编译到目标模型、照常按 [checklist.zh-CN.md](checklist.zh-CN.md) 复查。

**验证方式是复现。** 用反推出的决策清单跑一次，与原片逐槽对照。对不上的槽就是反推错了——这比任何纸面推敲都便宜。

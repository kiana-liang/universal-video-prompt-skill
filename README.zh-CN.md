## 它解决什么

### 1. 复刻一条爆款，抄了提示词还是做不出来

你抄到的是**措辞**，抄不到的是背后的**决策逻辑**——为什么用这个术语而不是那个、哪些东西必须不许变、每一段结束时画面上该有什么。这些不写在提示词的字面上，但它们决定了成片。

所以第一个用法就是**反推**：从一条成片、一张参考图或别人的提示词，还原出背后那份决策，再换成你的题材重新编译。

⚠️ 反推有个特有的坑：**在成片上量到的精度，不等于该写进决策清单的精度**。你在别人片子里量到帧级的音画同步，照抄成秒级时间戳会让你这一版更差——因为那个精度可能不是提示词给的，是模型自己给的。所以反推必须多一步归因：**这条特征是提示词给的，还是模型给的？**

### 2. 一个风格成了，想换主题反复用

换主题的时候你以为只换了题材，其实很容易把上一条片子的**美术方向**一起搬过来。

真实翻过一次：新题材要的是"空"，大色块加大片留白；而沿用下来的那几个风格词指向的是"满"，高密度、高饱和。两者几乎相反，等于给一部靠留白讲话的片子开了一副堆满的处方。

**麻烦在于逐条检查发现不了。** 每一条约束都在正常生效，生效的方向是另一条片子的。检查表上是满分，片子就是不对。

所以换主题有个固定流程：先取出这个片型真正不能变的那几条（去掉任何一条它就不是它了），其余逐项从零重填，**填完退一步再对一次方向**——这几个风格词指向的方向，和我这条片子本身是同一个吗？

### 3. 写了一大堆，效果不对，不知道该改哪一行

因为大部分行**没法检查**。「保持一致」「有张力」「电影感」——生成完你无法判断它有没有生效，出问题时也就无从下手。

核心动作只有一个：**把不可验证的翻译成可验证的**。

| 别写 | 改写成 |
|---|---|
| 「保持一致」 | 每一段结束时**可见的**末态 |
| 「紧张」 | 2–4 个可观察线索：视线、眉、嘴、呼吸、手 |
| 「节奏快一点」 | 每段的时间预算 |
| 「最慢最安静的一段」 | 那一段**发生的事**，用因果把张力接起来 |

最后一行是实测教训：一段写成「全片最慢最安静的一段」，模型把它读成**"这一段不发生事件"**，出来是主体保持同一个姿势缓慢位移，该段指定的几件事一件没发生。

### 4. 改了好几版越改越差，说不清哪一版动了什么

因为改动散在提示词里，没法单变量对照。决策清单本身就是一份**可 diff 的决策记录**——每版只改一处、其余一字不动，才能知道是哪一处起了作用。

这也是唯一能让"这版更好"这句话站得住的方式。

### 5. 贵模型抽卡烧不起

旗舰模型抽一次卡的成本，够在便宜模型上跑十次。**迭代在便宜的那条上做，定稿了再去跑贵的**——前提是两次用的是同一份决策清单，只换编译目标，不重写。

## 内置了什么

**5 个片型 DNA · 4 个跑通的完整案例 · 6 个模型档案 · 20 条实测记录。**

案例库里不是模板，是**跑通过的完整提示词和它的观测记录**——每一条都写明"写了什么 → 观测到什么"，包括：

- **四个模型跑同一份提示词**的逐字对照（同一份决策清单，只改提交参数）
- 一次**四段接龙**的完整迭代，六版
- 一份**七槽填了六槽**的完整决策清单，含九段时序与每段末态
- 6 张模型档案：SD2.0 / SD2.5 / MiniMax H3 / HappyHorse 1.1 / Kling v3.0 Pro / Turbo
  ——寻址语法、时长上限、时序遵循度、素材传入格式、已知失败模式
- 一份零依赖的节奏测量脚本（`tools/analyze_rhythm.py`），那些数值结论都能自己复现

另有 6 条形状示范，**明确标注未经实测**——它们只演示"这一槽长什么样"，不构成"这样写有效"的证据。

## 「决策清单」是什么

它不是提示词，是**一条提示词背后的决策**——跟"用什么话把它说出来"分开存放。

| | 决策清单 | 提示词 |
|---|---|---|
| 内容 | 主角全片同一件外套；第 2 段结束时刀已经在桌上；参考图只控脸不控背景 | `@image1 控角色的脸、发型和外套。不要用它的背景或构图。` |
| 跟模型的关系 | **无关**。换模型不用改 | **相关**。随模型变 |
| 形态 | 一张三层结构的槽位表 | 一段能直接粘进去跑的文字 |

所以整套东西的意思是：**决策写一次，其余按模型翻译。**

那个"其余"具体指什么值得说清楚，因为它是跨模型最容易出错的地方，一共三类：**寻址语法**（`@image1` 还是「参考图 1」）、**反默认词**（专治某个模型脾气的话）、**时长与分辨率枚举**。这三类一家一个样，本 skill 统称为**方言**——编译时才翻译，决策清单里不写。

> 📌 英文文档与文件名里，「决策清单」这个概念叫 `spec`（specification），所以你会看到 `spec-format.zh-CN.md` 这样的文件名。**文件名是跨语言的标识符，不翻译**；中文正文一律叫决策清单。

## 每写一行提示词，先过两个问题

### 一、这行提示词管多大范围？

写错范围是漂移最常见的原因，而且症状会骗人：前几段完全正确，后面突然消失。

| 层 | 管什么 | 内容 |
|---|---|---|
| ① 全局层 | 整条片子 | 片型、场景、风格、导演命题、运镜原则、〔按需〕持续叠层、〔按需〕手法词表 |
| ② 锁定层 | 任何不许漂的东西 | 身份、〔有素材时〕参考素材角色、音频源、〔有配角时〕配角调度、连续性、〔有内容风险时〕负向 |
| ③ 时序层 | 某一段 | 分段事件、每段末态 |
| **＋** | 上面装不下的 | **自己加的槽**，放进它作用域所属的那一层 |

**写在第 1 段里的全局规则，到第 4 段就不管用了。**

> 📌 skill 内部把这三层叫「桶①②③」（bucket），是同一个东西。

### 二、这行提示词生成完之后，能不能在成片上检查？

检查不了的行，出问题时也调不了。改写方法见上面第 3 节那张表。

⚠️ **可验证不等于锁对了维度。** 一条锁可以被完全满足、同时完全失效——实测：锁「保持平面、不要写实」，两个不同模型都严格照做，都给出光滑矢量描边。平面？是。手绘？完全不是。锁瞄在了「平面性」上，而承载概念的属性是「看得见工具痕迹」。

**判据：模型能不能满足这句话、同时把我要的东西丢掉？** 能，那这条锁瞄的是副作用而不是成因。

## 决策清单长什么样

三层结构，每层若干槽：

```text
[① 全局层]
  片型：      多轴术语合成 + 参照物锚点 + 各自的配平禁令
  场景：      在哪里、什么时候
  风格：      视觉处理、配色、光的行为（只写看得见的）
  导演命题：  一句话——这条片子存在的那个念头
  运镜原则：  管住全片的规则，不是镜头清单
  持续叠层：  〔按需〕每一帧都压在画面上的那一层，以及它自己怎么动
  手法词表：  〔按需〕全片可调用的具名动效与转场，不是逐拍指派

[② 锁定层]
  身份：      谁或什么必须保持不变，靠哪些不变量
  参考角色：  〔有素材时〕每份素材——控什么，以及不许从它拿什么
  音频源：    原生、外部音轨、还是静音
  配角调度：  〔有配角时〕位置，以及不许做什么
  连续性：    整条片子必须成立的东西
  负向：      〔有内容风险时〕只写具体风险

[③ 时序层]
  粒度：      不写 | 分段 | 秒级   （写下面的内容之前先定）
  第 1..n 段：每段一个主要变化
  每段末态：  这一段结束时什么是可见的

[+ 自定义槽]  这条片子需要、而上面装不下的东西
```

**这张表是可用工具的清单，不是待办清单。** 没有任何一槽是必填的——空着是判断结果，不是漏填；装不下就加槽，别硬塞进最接近的那个。

案例库里那份完整示例，七槽里就有一槽是空的，而且**空着正是它值得看的地方**。

## 骨与皮：这套东西最不一样的地方

先把两个词说清楚，后面全靠它们：

> **骨 = 可复用的方法。** 判据、结构、失败的形状。换一条片子照样成立。
> **皮 = 某一次的具体填法。** 术语字符串、禁令措辞、元素清单、完整分镜。只对那一条片子成立。

一般的提示词仓库给你一堆能抄的例子。**这套东西反过来——把能抄的全部关进隔离区，正文只留骨。**

原因就是前面「换主题」那个失败：翻车的根因**是文档结构，不是疏忽**。当示例和方法写在同一页上，人就会照着填；靠"提醒自己小心"挡不住，只能靠结构挡。

| 隔离区 | 防什么 | 顶部标识 |
|---|---|---|
| [`case-library.zh-CN.md`](references/case-library.zh-CN.md) | 防**多抄**。所有可被复制粘贴的具体元素全在这里 | ⛔ 先把你自己的槽写完 |
| [`film-types.zh-CN.md`](references/film-types.zh-CN.md) | 防**误载**。五张跑过的皮，按片型分组 | ⛔ 先确认你的片子跟它同一类 |
| [`observations.zh-CN.md`](references/observations.zh-CN.md) | 防**少写**。跑过的逐模型观测与失败模式 | ⛔ 写作期不读 |

第三个最反直觉：**为什么"我对模型能力的理解"也要隔离？**

因为**少写比多抄更难发现**。抄错了看得出来，而"因为觉得模型做不好所以没写"这件事，**在输出里没有任何痕迹**——你只会看到效果没达到预期，却找不到原因，因为那句话从来没出现过。

隔离区**按片子分组，不按槽分组**。这是故意的：要用其中一条，你得先承认"我的片子和这部是同一类"，那个动作本身就是筛子。

## 宪法：十二条元规则

规则多了会互相冲突，所以要有一层管"怎么用这些规则"的东西。宪法**优先于本 skill 其他任何文件里的具体建议**。

**关于示例（四条）**

1. 示例不是 DNA，示例只是**皮的一个样本**
2. 填槽顺序是「**先写，再看**」——先只看这条片子写出来，写完才允许看示例
3. 示例**物理隔离**，不靠自律。**规则本身也可以是皮**
4. 相邻槽的示例**不得同源**

**关于槽（三条）**

5. **没有任何槽是必填的**，空着是判断结果
6. **槽集合是开放的**，装不下就加槽
7. **放错层是头号错误**

**关于边界（五条）**

8. 模型档案**不能反向删改母版**——一个槽在某个模型上失效，是那张档案的事实
9. 不要把「你对模型能力的理解」写进规则——档案只记「我写了 X，观测到 Y」，不记「X 没用」
10. **先把决策清单写全，再让硬约束触发降级**。「我觉得这个模型可能做不好」不是硬约束
11. 别把**某场景的默认值抬成全局规则**
12. **规则不替代审核**

完整版 → [`references/constitution.zh-CN.md`](references/constitution.zh-CN.md)

### 第十条为什么是单向的

只禁「因为观测而少写」，不禁「因为观测而敢写」——两个方向都是拿一次观测决定下一步，但**代价差一个量级**：

| 情况 | 严重性 |
|---|---|
| 用户强调过必须要的东西，少写了 | **最严重**。不是"效果差一点"，是**没交付**，而且在输出里**没有痕迹** |
| 没强调、看完才发现想要 | 正常。在皮上加就是了，这是迭代常态 |
| 写多了 | 轻。看得见、能删 |

**规则按代价设计，不按逻辑对称设计。**

## 换模型时会变的三层

决策清单可移植，它内部的行不都可移植。跨模型最常见的错误是**把偏置层的行当成语言层的行**——把在某个模型上有效的反默认后缀，照抄给另一个模型并假设它照样有用。

| 层 | 内容 | 处理 | 存哪 |
|---|---|---|---|
| **语言层** | 三层结构、末态、可观察线索、术语双写 | 照写即可，全模型通用 | 决策清单 |
| **偏置层** | 反默认后缀、负向锁、转场词、素材寻址方言 | 一模型一张档案，**只能实测** | 模型档案 |
| **能力位层** | 素材数量、能否多镜头、能否硬切、时长、时序遵循度 | 先探测，再降级 | 模型档案 |

**抗方言的通法＝术语 + 可观察描述双写。** 认识术语的模型走捷径，不认识的走描述，一份提示词通吃。

⚠️ **已发布的枚举值是假设，不是限制。** 文档写的范围经常比实际能提交的更窄，同一个页面还会自己打架（实测见过同一页三处写了三个不同的时长范围）。**直接提交你真正想要的值，让 API 来回答。**

> ⚠️ 但「被拒不创建任务、不花钱」**只在直连厂商时成立**。在聚合平台上可能不成立：网关提交时不校验，返回成功并创建任务，再由上游拒掉。**看到「任务创建成功」不等于参数被接受**——所以在聚合路线上探边界，先拿最短时长、最低分辨率试那个参数，别用完整任务去试。

    ├── analyze_rhythm.py             节奏客观测量，零依赖
    └── check-sync.py                 中英同步检查
```

`*` 表示中英各一份。**三个隔离区只有中文**，这是设计决定：它们装的是具体术语措辞，翻译会造出第二套皮——同一个术语两种译法，下一个人不知道该抄哪个。agent 读中文没有障碍。

npx skills add kiana-liang/universal-video-prompt-skill
```

## 执行

编译好的提示词与厂商无关，交给任何能跑目标模型的服务即可。**用户指定的服务永远优先。**

一份决策清单要打到多个模型时，聚合平台摩擦最小：一套凭证覆盖全部模型，而且共享执行环境——输出差异才能归因到**模型本身**而不是链路。不受控的对比不值得跑。[Atlas Cloud](https://www.atlascloud.ai) 是本 skill 的文档默认路线，基于这个理由；直连厂商时编译步骤完全不变，只有寻址语法和提交调用不同。

走 Atlas 路线的话，官方 skill 可以一起装上，省掉自己写提交与轮询：

```bash
npx skills add AtlasCloudAI/atlas-cloud-skills --skill atlas-cloud
```

无论走哪条路线，生成都要花钱，[`execution`](references/execution.zh-CN.md) 那套计费任务状态机不可省：提交的当下就记 prediction ID；`processing` 是进行中不是失败；**任务 completed 不等于本地文件可用**。

## 它不做什么

- **不替代审核。** 它减少的是无效迭代——把已经付过学费的失败固化下来，不必重踩。它不给输出盖章。每条规则都有例外，判断权在做片子的人手上，尤其是**动态、节奏、整体调性**这三样规则和静帧都覆盖不到的东西。
- **不做生产流程判断。** 「这个转场是不是该由剪辑来做」不属于这里——那是成本判断伪装成能力判断，后果是预先划走一整类手法，那格档案永远填不上。
- **不承诺确定性。** 时间戳分配的是时间预算，不是帧精确的剪辑点；边界帧在视觉上衔接，不是逐像素拼接。
